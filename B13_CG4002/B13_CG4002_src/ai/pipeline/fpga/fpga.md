# `fpga/`

Synthesizes the network into an IP core with Vitis HLS, then wraps it in a Zynq UltraScale+ block
design with Vivado and produces the bitstream for the Ultra96-V2.

## Entry point

Stages 4 and 5 of `pipeline.sh`, or on their own:

```bash
../scripts/hls.sh [width] [build] [cosim vectors] [mode]
../scripts/vivado.sh [width] [build] [bd]
```

`.bat` on Windows, same arguments. Width defaults to the one the export selected, build to `A`.
Both need Vitis HLS and Vivado 2022.1. Set `VITIS_HLS` or `VIVADO` to the executable if it is not
found.

| HLS mode | Runs |
|---|---|
| `full` (default) | C simulation, synthesis, co-simulation, IP export |
| `synth-export` | Synthesis, IP export |
| `cosim-only` | Co-simulation of an existing synthesis |
| `cosim-export` | Co-simulation and IP export of an existing synthesis |

`vivado.sh` with `bd` stops after the block design is validated. Otherwise it implements the
design and fails if timing is not met. It writes:

| Output | Holds |
|---|---|
| `hls/hls_w<N>_<B>/` | The Vitis HLS project. The packaged IP is in `sol/impl/ip/`. |
| `vivado/vivado_w<N>_<B>/` | The Vivado project |
| `vivado/bit/nn_w<N>_<B>.bit`, `.hwh` | The bitstream and the hardware handoff PYNQ reads |
| `vivado/reports/` | Post-implementation timing, utilization and power |

## Structure

```
fpga/
├── hls/
│   ├── nn_infer.cpp         the network, hand-written
│   ├── nn_infer.hpp
│   ├── nn_tb.cpp            testbench, compares against the golden vectors
│   ├── params.hpp           picks the generated headers for the selected width
│   ├── weights.hpp
│   ├── golden.h
│   ├── *_w<N>.*             generated by export/
│   └── tcl/
│       ├── run_hls.tcl      entry point
│       ├── configure.tcl    part, clock and the directives of each build
│       ├── csim.tcl
│       ├── csynth.tcl
│       ├── cosim.tcl
│       ├── cosim_workaround.tcl
│       ├── export_ip.tcl
│       └── nn_width.tcl     reads the selected width
└── vivado/
    └── tcl/
        ├── install_board.tcl
        ├── block_design.tcl entry point
        ├── implement.tcl
        └── session.tcl
```

## Files

| File | Does |
|---|---|
| `hls/nn_infer.cpp` | The forward pass in synthesizable C++. Takes one $12 \times 32$ window of 8-bit integers and returns the 10 class scores. |
| `hls/nn_tb.cpp` | Runs every golden input through `nn_infer` and compares the logits bit for bit |
| `hls/params.hpp`, `weights.hpp`, `golden.h` | Include the generated headers for the width in `selected_width.hpp`, so no hand-written file names a width |
| `hls/tcl/run_hls.tcl` | Runs the HLS flow in the order the mode asks for |
| `hls/tcl/configure.tcl` | The part (`xczu3eg-sbva484-1-i`), the 100 MHz clock, and the directives of each build |
| `hls/tcl/cosim_workaround.tcl` | Works around two Vitis HLS 2022.1 co-simulation problems on Windows |
| `vivado/tcl/install_board.tcl` | Installs the Avnet Ultra96-V2 board files if they are missing |
| `vivado/tcl/block_design.tcl` | Connects the IP to the PS over AXI, then implements the design and writes the bitstream |
| `vivado/tcl/implement.tcl` | Synthesis, place and route, run in a fresh process |
| `vivado/tcl/session.tcl` | Settings shared by every Vivado process |

## Builds

The build letter selects which HLS directives `configure.tcl` applies. `A` ships.

| Build | Directives |
|---|---|
| `A` | None |
| `B` | Pipeline both convolution time loops |
| `C` | `B`, plus unrolling the input-channel loops. Identical to `B`. |
| `D` | `C`, plus a cyclic partition of the conv1 output and the pooled output |
| `E` | Unroll conv2's input-channel loop by 8 and pipeline it, with the arrays it reads partitioned |
